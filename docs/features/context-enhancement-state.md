# 上下文增强、Pi 回退与状态标识

## 1. 文档角色

本文定义自动工作上下文优化的 Pi 对话回退兼容行为和运行状态。产品目标见 [`../../PRODUCT.md`](../../PRODUCT.md)，系统责任见 [`../../ARCHITECTURE.md`](../../ARCHITECTURE.md)，验证要求见 [`../validation/context-enhancement-state.md`](../validation/context-enhancement-state.md)。

OpenViking 接口、上下文预算、记忆生成算法和 UI 实现细节分别由系统与模块设计承担。

## 2. 目标与边界

扩展在保持 Pi 原有使用方式的前提下提供自动记忆和有界工作上下文。Pi session 历史、当前 leaf、branch 关系、对话回退和原生压缩构成权威能力；扩展围绕当前路线提供增强，Pi 回退和分支操作保持原有语义与时序。

扩展运行期间，用户必须持续看到当前模型输入实际采用以下哪条路径：

- **增强记忆**：本次模型上下文采用扩展为当前路线构造并确认有效的增强上下文；
- **Pi 原生**：本次模型上下文采用 Pi 原生记忆与压缩。

状态标识以经过 Pi `context` hook 的对话任务模型实际采用路径为准；OpenViking 在线、后台任务以及 Pi 内部 tree/compaction 摘要请求属于运行过程，不改变对话采用状态。

## 3. Pi 对话回退与分支行为

当用户通过 Pi 对话回退、`/tree`、`/fork`、`/clone` 或 `/resume` 改变当前位置或 session 时：

1. Pi 按原生语义完成操作，扩展读取操作后的会话状态；
2. 新 session 身份、当前 leaf 以及从根到 leaf 的路线成为唯一有效输入；
3. 当前路线成为增强上下文的唯一采用范围，每个后台结果按其输入路线接受核验；
4. 新路线增强结果准备期间，模型采用 Pi 原生上下文与压缩，状态显示“Pi 原生”；
5. 与当前 session 和路线一致且确认有效的结果进入后续模型输入；
6. Pi 在树导航中生成的 branch summary 成为新路线权威条目后，按该路线来源处理。

再次进入已处理路线时，已有派生结果按当前 Pi 路线重新核验后进入采用流程。

## 4. 压缩、降级与恢复

Pi 原生压缩承担持续可用的安全底座。当前显示“Pi 原生”时，模型使用 Pi 构造的消息，手动、阈值和上下文溢出触发的原生压缩均按原有流程执行；overflow 压缩的自动重试在本轮 agent settled 前强制使用 Pi 原生消息，不能重新采用刚刚超限的增强 payload。

增强结果处于准备、过期、超时、不一致或后端故障与恢复状态时，本次模型调用采用 Pi 原生路径并显示“Pi 原生”。后台恢复与 Pi 任务并行；结果重新通过当前路线核验并实际进入模型输入后，状态变为“增强记忆”。

Pi Agent 循环独立于增强处理和状态展示持续运行。

## 5. 状态展示

状态使用 Pi 扩展提供的持久状态区域展示，并与会话消息和模型上下文保持分离。状态在 session 启动、路线变化、上下文采用、降级和恢复后随实际路径更新。

状态文字可以随界面语言调整，并始终明确区分“增强记忆”和“Pi 原生”；在线、就绪和错误信息保留为诊断信息。

## 6. 完成条件

- Pi 的回退、树导航、fork、clone、resume 和原生压缩在扩展启用时保持原有结果；
- 路线变化后的 Provider 请求只包含当前路线及其确认有效的增强内容；
- 新路线增强结果准备或恢复期间，Pi 任务采用原生记忆与压缩继续运行；
- 每次 Provider 请求对应的状态与该请求实际采用路径一致；
- 后端恢复结果在完成当前路线核验并实际采用后切换为增强状态；
- 状态展示与模型上下文分离，Pi 可用性由原生路径持续保证。
