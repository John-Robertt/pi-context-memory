# 增强记忆工作上下文与运行状态

## 1. 文档角色

本文定义扩展启用后，用户和任务模型可以观察到的增强记忆、自动压缩、故障阻断与恢复行为。产品目标见 [`../../PRODUCT.md`](../../PRODUCT.md)，系统协作见 [`../system/context-enhancement.md`](../system/context-enhancement.md)，验证要求见 [`../validation/context-enhancement-state.md`](../validation/context-enhancement-state.md)。

本文不规定 OpenViking 协议、上下文预算、内部路线状态或 UI 实现细节。

## 2. 目标与边界

扩展启用期间，本扩展负责任务记忆、自己构造的工作上下文和相关 hook 处理。Pi 继续负责 Agent、session 历史、工具执行、tree、branch、扩展调度、Provider transport 和用户交互；本扩展不要求 Pi 或其它扩展改变行为。

本扩展在 context 只产生 `allow(enhancedContext, proof) | block(fault)`。allow 输出到达本 Provider handler 后分为 verified/rejected，未到达则记 unobserved；block 停止本扩展自己的增强处理并诊断。

Pi 或其它扩展在本 handler 之后的变化不属于本扩展证明。最终采用由 transport 观测确认；无法确认时显示兼容性结论，由用户决定是否继续、调整组合或禁用扩展。

用户若选择退出当前 Pi、禁用扩展并重新启动，后续行为由 Pi 自身负责；这不是本扩展的请求级 fallback。

## 3. 用户状态

状态栏只展示：

- **增强记忆 · 初始化中**：OpenViking 运行实例、配置和记忆模型实际能力正在建立；
- **增强记忆**：本扩展拥有的增强运行正常；
- **增强记忆 · 故障**：本扩展无法继续确认增强结果，诊断说明责任边界。

状态只描述本扩展拥有的运行，不证明后续 handler 或 transport 最终采用。后台 refresh、等待和队列正常进行时仍显示“增强记忆”。

## 4. 正常任务行为

### 4.1 跨轮历史

系统自动将当前任务所需的目标、约束、有效事实、必要证据和近期工作构造成有界增强历史。已核验记忆与当前路线新近来源足够时，后台记忆刷新不阻塞任务；只有缺少可信或有界历史时，本次请求等待必要刷新。退出模型输入的信息继续保存在 Pi session 来源和长时记忆中，并可按需召回。

### 4.2 当前回合工具结果

一个 assistant 消息中的工具调用和对应结果作为完整批次处理：

- 预算允许时保持 Pi Provider 基线的消息结构和顺序，只对本扩展拥有的稳定 locator 做精确规范化；
- 批次或当前回合超过预算时，形成有界、来源可恢复的投影；
- 投影保留结构状态、block 类型、固定 head/tail、哈希与来源入口，不解析正文重要性；
- Provider 要求的工具调用与结果配对保持合法。

并行、快速和大输出使用同一结构规则，不要求用户控制速度或手工压缩。Pi fullOutputPath 先转稳定来源；来源未恢复时本扩展不确认依赖它的输出，transport 另行观测。

### 4.3 首轮与连续请求

用户在“增强记忆 · 初始化中”提交任务时，本次请求加入初始化屏障；能力验证成功后，同一请求以合法空历史增强上下文继续，不要求用户重复提交。后续请求优先使用与当前路线兼容的已核验记忆和新近来源；后台刷新尚未完成但该组合仍可信且有界时，请求直接发送。

初始化、续租、刷新和必要等待不改变本扩展的构造规则。能力证明临近到期时旧证明仍有效，续租在后台执行；到期或缺少可用记忆/来源/预算时才等待。用户取消只终止本次等待；必要能力失败时，本扩展不确认增强输出并调用 `ctx.abort()`。handler 返回与 Pi/transport 实际结果分别观测。

## 5. 自动压缩与会话操作

### 5.1 自动压缩与用量

扩展持续控制自己构造的模型工作上下文大小，用户不需要主动执行 `/compact`。Pi 发出 compaction 事件时，本扩展通过公开 hook 返回取消意见并记录可观测结果；它不把该返回值表述为 Pi 或其它扩展必须遵守的行为。

交互界面保留 Pi 的任务模型上下文百分比、窗口、累计 usage、费用、模型和 branch 信息，并以 `(增强)` 表示本扩展当前负责的上下文构造；该显示不宣称控制 Pi compaction 或其它扩展。百分比不表示记忆模型用量，也不决定请求能否发送；扩展不修改 Pi 持久化 compaction 设置。

### 5.2 会话操作

对话回退、`/tree`、`/fork`、`/clone`、`/resume` 和 reload 保持 Pi 的用户操作语义。操作后的当前 session、session file、leaf 和 branch 成为后续增强请求的唯一范围。

用户选择 tree summary 时，本扩展在 suite 所选且已通过行为探针的 PiProtocolProfile hook 中请求按无摘要方式导航；未验证或实际结果不同则只报告 `host-behavior-unverified`。扩展不取消、重排或修改其它 handler。操作后的实际 leaf、branch 和已有 summary entry 仍由 Pi 定义；本扩展只是不把 summary 文本作为记忆来源。

## 6. 故障与恢复

以下情况进入“增强记忆 · 故障”：
- 当前 Pi session 没有可恢复的持久化 session file；
- 记忆模型配置或认证无效；
- OpenViking 受管实例不可用；
- 记忆模型实际能力验证失败；
- 当前来源无法可靠保存或恢复；
- 必要检查点刷新失败、到达支持 profile 的运行边界，或当前路线无法形成可信有界历史；
- OpenViking 返回未知、不完整或不可信内容；
- 当前回合无法在保持工具协议和必要信息的前提下进入预算；
- 当前任务 Provider API 没有可核验的 payload 适配；
- 本扩展的 Provider hook 时点无法核对与当前请求一致的增强证明。

故障发生后：

1. 当前 Pi session、branch 和来源保持不变；
2. 本扩展不再确认新的增强输出；
3. 状态和诊断给出配置、服务、模型、来源、路线或内容层面的原因；
4. 系统不自动重放中断请求或工具操作；
5. 诊断不自动修改 Pi、Provider、模型、其它扩展或加载顺序；
6. 修复、继续当前组合、重启服务、禁用扩展或重新提交任务由用户决定。

## 7. 完成条件

- 本扩展发布的增强上下文都携带当前代际和精确路线的合法证明；
- `before_provider_request` 结论明确限定在本 handler 时点，实际采用由 transport 观测；
- 后台刷新正常时不形成用户状态或普遍等待；只有可信上下文确实不足时才建立必要屏障；
- 多工具、大输出和快速结果保持上下文有界、协议完整和来源可恢复；
- compaction/tree hook 只表达本扩展处理意见；宿主结果符合时记录成功，不符合时记录兼容性诊断而不修改其它组件；
- session/branch 操作后，本扩展只从 Pi 实际当前路线构造来源、记忆和增强输出；
- 故障状态提供可操作诊断，恢复不自动重放任务；
- 用户若禁用扩展并重启，Pi 后续行为不再由本扩展声明。
