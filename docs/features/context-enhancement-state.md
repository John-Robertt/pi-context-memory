# 上下文增强、Pi 回退与状态标识

## 1. 文档角色

本文定义自动工作上下文优化的 Pi 对话回退兼容行为和运行状态。产品目标见 [`../../PRODUCT.md`](../../PRODUCT.md)，系统责任见 [`../../ARCHITECTURE.md`](../../ARCHITECTURE.md)，验证要求见 [`../validation/context-enhancement-state.md`](../validation/context-enhancement-state.md)。

OpenViking 接口、上下文预算、记忆生成算法和 UI 实现细节分别由系统与模块设计承担。

## 2. 目标与边界

扩展在保持 Pi 原有使用方式的前提下提供自动记忆和有界工作上下文。Pi session 历史、当前 leaf、branch 关系、对话回退和原生压缩构成权威能力；扩展围绕当前路线提供增强，Pi 回退和分支操作保持原有语义与时序。

扩展运行期间，用户必须持续看到增强记忆的实时生命周期：

- **增强记忆 · 初始化中**：正在确认当前运行实例或重新初始化服务连接；
- **增强记忆 · 生效中**：服务可用，当前路线正在准备、核验或恢复增强上下文；
- **增强记忆**：当前可用增强上下文已经进入任务模型输入；
- **Pi 原生**：增强服务不可用，本次任务只能强制由 Pi 原生记忆与压缩路径接续。

状态标识表达增强能力是否正在建立、已经生效或不可用，不由每次模型请求的 `enhanced|pi-native` 观测直接覆盖。正常初始化、路线准备、tree/compaction 后重建以及恢复过程始终保留增强标识；每次 Provider 请求的实际采用路径另行记录，用于采用率、降级原因和 Provider payload 一致性验证。

## 3. Pi 对话回退与分支行为

当用户通过 Pi 对话回退、`/tree`、`/fork`、`/clone` 或 `/resume` 改变当前位置或 session 时：

1. Pi 按原生语义完成操作，扩展读取操作后的会话状态；
2. 新 session 身份、当前 leaf 以及从根到 leaf 的路线成为唯一有效输入；
3. 当前路线成为增强上下文的唯一采用范围，每个后台结果按其输入路线接受核验；
4. 新路线增强结果准备期间，模型可由 Pi 原生上下文与压缩保持连续，状态显示“增强记忆 · 生效中”而不是原生标识；
5. 与当前 session 和路线一致且确认有效的结果进入后续模型输入后，状态显示“增强记忆”；
6. Pi 在树导航中生成的 branch summary 成为新路线权威条目后，按该路线来源处理。

再次进入已处理路线时，已有派生结果按当前 Pi 路线重新核验后进入采用流程。

## 4. 压缩、降级与恢复

Pi 原生压缩承担持续可用的安全底座。只有增强服务不可用并强制接续时状态显示“Pi 原生”。手动、阈值和上下文溢出触发的原生压缩仍按 Pi 原有流程执行；overflow 压缩的自动重试在本轮 agent settled 前强制使用 Pi 原生消息，不能重新采用刚刚超限的增强 payload，但服务仍可工作时状态保持“增强记忆 · 生效中”。

启动、实际服务重启和运行实例检查时显示“增强记忆 · 初始化中”；结果正在准备、过期重建或后端恢复时显示“增强记忆 · 生效中”。配置文件表示下一次重启目标，修改、清空或暂时写错配置都不影响当前 ready 实例；重启预检失败也继续使用旧实例。只有当前运行实例停止、准备失败或超时使增强服务无法交付时，状态才变为“Pi 原生”。后台恢复与 Pi 任务并行；新实例或恢复结果重新通过当前路线核验后先回到“增强记忆 · 生效中”，实际进入模型输入后显示“增强记忆”。

Pi Agent 循环独立于增强处理和状态展示持续运行。

## 5. 状态展示

状态使用 Pi 扩展提供的持久状态区域展示，并与会话消息、模型上下文和实际采用观测保持分离。状态在 session 启动、配置检查、路线准备、增强采用、故障和恢复时按生命周期实时更新；session 关闭时清除。

状态文字固定为“增强记忆 · 初始化中”“增强记忆 · 生效中”“增强记忆”和“Pi 原生”；原生标识不附加错误原因，详细配置、运行模型、最近实际采用路径和错误继续由 `/memory-model`、通知及运行观测承担。

## 6. 完成条件

- Pi 的回退、树导航、fork、clone、resume 和原生压缩在扩展启用时保持原有结果；
- 路线变化后的 Provider 请求只包含当前路线及其确认有效的增强内容；
- 新路线增强结果准备或恢复期间，Pi 任务采用原生记忆与压缩继续运行，状态保持“增强记忆 · 生效中”；
- 每次 Provider 请求的实际采用路径独立记录；正常准备中的原生请求不能把状态覆盖为“Pi 原生”；
- 服务不可用时只显示“Pi 原生”，恢复时依次展示初始化、生效中和增强记忆状态；
- 状态展示与模型上下文分离，Pi 可用性由原生路径持续保证。
