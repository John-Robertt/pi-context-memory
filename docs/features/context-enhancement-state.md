# 增强记忆工作上下文与运行状态

## 1. 文档角色

本文定义扩展启用后，用户和任务模型可以观察到的增强记忆、自动压缩、故障阻断与恢复行为。产品目标见 [`../../PRODUCT.md`](../../PRODUCT.md)，系统协作见 [`../system/context-enhancement.md`](../system/context-enhancement.md)，验证要求见 [`../validation/context-enhancement-state.md`](../validation/context-enhancement-state.md)。

本文不规定 OpenViking 协议、上下文预算、内部路线状态或 UI 实现细节。

## 2. 目标与边界

扩展启用期间，增强记忆负责任务模型的工作上下文和自动压缩。Pi 继续负责 Agent、session 历史、工具执行、tree、branch 和用户交互；任务模型请求只使用增强记忆核验通过的上下文。

每个请求具有两种结果：

- 通过当前运行代际、session、branch、来源、内容和预算核验后发送；
- 在 Provider 发送前被阻断，并给出故障诊断。

Pi 原生上下文和压缩属于扩展未启用的独立运行方式。用户退出当前 Pi、禁用扩展并重新启动后进入该方式。

## 3. 用户状态

状态栏只展示：

- **增强记忆 · 初始化中**：OpenViking 运行实例、配置和记忆模型实际能力正在建立；
- **增强记忆**：增强路径正常运行；
- **增强记忆 · 故障**：新任务模型请求已阻断，需要用户处理诊断。

当前路线准备、等待、排队、镜像更新和 Working Memory 后台任务属于内部状态。它们正常进行时状态保持“增强记忆”，不向用户展示单独阶段。

## 4. 正常任务行为

### 4.1 跨轮历史

系统自动将当前任务所需的目标、约束、有效事实、必要证据和近期工作构造成有界增强历史。退出模型输入的信息继续保存在 Pi session 来源和长时记忆中，并可按需召回。

### 4.2 当前回合工具结果

一个 assistant 消息中的工具调用和对应结果作为完整批次处理：

- 预算允许时保持原始消息和顺序；
- 批次或当前回合超过预算时，形成有界、来源可恢复的投影；
- 执行状态、错误、否定结果、影响后续行动的内容和来源入口持续可用；
- Provider 要求的工具调用与结果配对保持合法。

并行工具、快速连续结果和单次大输出都使用同一行为，不要求用户控制输出速度或手工压缩。

### 4.3 首轮与连续请求

用户在“增强记忆 · 初始化中”提交任务时，本次请求加入初始化屏障；能力验证成功后，同一请求以合法空历史增强上下文继续，不要求用户重复提交。后续请求等待自己的精确路线和有界当前回合准备完成后发送。

初始化、能力续租和路线等待不改变请求路径。用户主动取消只终止本次等待且不发送 Provider 请求；必要能力失败或操作期限结束时，本次请求被阻断并进入故障状态。

## 5. 自动压缩与会话操作

扩展启用后，增强记忆持续控制模型工作上下文大小，用户不需要主动执行 `/compact`。Pi compaction 事件由扩展接管，不产生独立的 Pi 摘要请求；增强 payload 超过模型限制时进入故障状态，由实现修正预算或投影问题。

对话回退、`/tree`、`/fork`、`/clone`、`/resume` 和 reload 保持 Pi 的用户操作语义。操作后的当前 session、session file、leaf 和 branch 成为后续增强请求的唯一范围。

`/tree` 只允许无 summary 导航。即使用户选择 summary，扩展也抑制 Pi 原生与扩展摘要生成，不创建 `branch_summary` entry，并提示本次按无摘要导航；导航完成后只以目标 leaf 和 branch 重建增强记忆。已有 summary entry 的文本不进入 VLM 或任务模型上下文。

## 6. 故障与恢复

以下情况进入“增强记忆 · 故障”：
- 当前 Pi session 没有可恢复的持久化 session file；
- 记忆模型配置或认证无效；
- OpenViking 受管实例不可用；
- 记忆模型实际能力验证失败；
- 当前来源无法可靠保存或恢复；
- 当前路线准备失败或超时；
- OpenViking 返回未知、不完整或不可信内容；
- 当前回合无法在保持工具协议和必要信息的前提下进入预算；
- 当前任务 Provider API 没有可核验的 payload 适配；
- 最终 Provider payload 缺少与当前请求一致的增强证明。

故障发生后：

1. 当前 Pi session、branch 和来源保持不变；
2. 新任务模型请求在 Provider 前被阻断；
3. 状态和诊断给出配置、服务、模型、来源、路线或内容层面的原因；
4. 系统不自动重放中断请求或工具操作；
5. 用户修复配置、服务或存储条件后显式执行 `/restart-viking`；需要更新扩展本身时重新启动 Pi；
6. 新运行代际验证通过后状态恢复为“增强记忆”，用户重新提交任务。

## 7. 完成条件

- 扩展启用后，所有已发送任务模型请求都携带当前代际和精确路线的合法增强上下文；
- 条件不成立的请求不进入 Provider；
- 内部路线准备不形成用户状态；
- 多工具、大输出和快速结果保持上下文有界、协议完整和来源可恢复；
- Pi compaction 被取消，tree summary 的模型请求和新 entry 均为零；
- session、branch、tree、fork、clone、resume 和 reload 后的请求只采用操作后的有效路线；
- 故障状态提供可操作诊断，恢复不自动重放任务；
- 禁用扩展并重新启动后，Pi 原生行为保持独立可用。
